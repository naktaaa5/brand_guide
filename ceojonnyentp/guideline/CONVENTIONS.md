# 집필 규약 — 조니(에이디솔루션) 가이드라인

이 문서만 읽고도 0부와 같은 결의 섹션을 쓸 수 있게 만든 규약이다.
정본 스펙은 `볼트/40_프로젝트/브랜드가이드라인/조니_AD솔루션/CP2_목차전개스펙_260807.md`,
수치 정본은 같은 폴더 `04_자산수집_260806/정본수치표_260808.md` 하나뿐이다.

**집필 순서: 스펙 주석 읽기 → 정본수치표에서 수치 꺼내기 → 마크업 → 반스코프 자가검열.**

## 최우선 편집·상호작용 원칙

이 절의 규칙은 이후 전달되는 디자인 템플릿, 스킨, 컴포넌트 라이브러리보다 우선한다. 템플릿과 충돌할 경우 템플릿을 수정하며, 아래 정보 위계와 상호작용을 템플릿에 맞추기 위해 생략하거나 변형하지 않는다.

1. 전략적으로 기억시켜야 할 판정 문장은 형광펜 효과로 표시한다. 핵심 구절 뒤에 색면을 깔고 글자색도 함께 바꾸되, 장마다 1~2개를 넘기지 않는다.
2. 실제 콘텐츠의 첫 등장은 본문 가까이에 콘텐츠 전용 플레이어로 제시한다. 계정명, 프로필, 캡션, 댓글 등 인스타그램 기본 임베드의 외곽 UI는 노출하지 않고 영상 또는 이미지인 순수 콘텐츠 영역만 보여준다.
3. 날짜와 조회수는 콘텐츠 프레임 위에 작은 라벨로 겹쳐 올린다. 콘텐츠 밖에 별도의 SNS 카드 헤더를 만들지 않는다.
4. 같은 콘텐츠가 뒤에서 재언급되면 큰 임베드를 반복하지 않는다. 콘텐츠 제목이나 첫 대사에 마우스를 올렸을 때 순수 콘텐츠 미리보기가 뜨고, 클릭하면 최초 임베드 위치 또는 원본 콘텐츠로 이동한다.
5. 모바일에는 호버가 없으므로 첫 탭은 미리보기 열기, 두 번째 탭은 최초 임베드 또는 원본 열기로 대체한다. 키보드 포커스에서도 동일한 미리보기가 열려야 한다.
6. 강조 문장과 콘텐츠 근거는 같은 시각 효과를 쓰지 않는다. 형광펜은 보고서의 판정, 플레이어와 호버 미리보기는 실제 콘텐츠 근거를 뜻한다.

인스타그램 공식 임베드는 계정과 캡션 UI를 제거할 수 없으므로 이 문서의 기본 표현으로 사용하지 않는다. 사용 권한이 확보된 원본 영상·다운로드 자산 또는 포스터 프레임과 자체 플레이어를 사용하고, 인스타그램 원본 링크는 접근 가능한 보조 링크로 남긴다.

## 0. 지금 이 파일의 상태

| 층 | 상태 |
|---|---|
| 마크업 구조 · 클래스 체계 | **확정.** 후속 집필자는 이걸 따른다. |
| 스킨(색·서체·여백 리듬) | **잠정.** 별도 디자인 패스에서 2~3안으로 교체된다. |

`index.html` 안에서 `<!-- N부 스펙 요약 (CP2) -->` 주석을 찾으면 그 부에 뭘 써야 하는지가 전부 나온다.
**주석은 집필이 끝나도 지우지 않는다** — 검수자가 스펙 대조에 쓴다.
지우는 것은 `.wip` 배지와 `.shell-note` 문단뿐이다.

## 1. 섹션 구조 — 한 부(部)의 골격

```html
<!-- N부 스펙 요약 (CP2) : … 집필 스펙 주석 … -->
<article class="chapter" id="pN">
  <div class="chapter__rail">
    <p class="rail-num">0N / 07</p>
    <h2 class="rail-name">어법</h2>
    <p class="rail-ko">한 줄 요지. 22자 안쪽.</p>
    <nav class="rail-sub" aria-label="N부 소목차">
      <a href="#s-xxx">소제목</a>   <!-- href 는 본문 h3 의 id 와 1:1 -->
    </nav>
  </div>

  <div class="chapter__body">
    <h2 class="at">N부 — 제목</h2>
    <p class="leadline">결론 한 문장. <em>강조 어절</em></p>
    <p>…</p>

    <h3 id="s-xxx"><span class="no">N-1</span>절 제목</h3>
    …

    <div class="close-part"><p>이 부의 지시를 한 문단으로.</p></div>
    <div class="chapter-next"><a href="#pN+1"><b>NEXT 0N+1</b><strong>다음 부 제목</strong></a></div>
  </div>
</article>
```

규칙:

- `id`는 `p0`~`p7`, `pa`(부록). 상단 `#partnav`·하단 `#botnav`의 `data-t` 값과 일치해야 네비가 붙는다.
- `rail-sub`의 앵커와 본문 `h3 id`는 반드시 1:1. 어긋나면 레일 현재 위치 표시가 죽는다.
- **`.leadline`은 각 부에 1개, 각 절에 최대 1개.** 결론 선행 장치이지 장식이 아니다.
  긴 문장을 넣지 않는다 — `max-width:24ch`가 걸려 있다.
- `.close-part`는 모든 부에 필수. **맺음 없이 끝나는 부는 없다.**
- 문서 전체의 클로징은 7부 끝에 온다. 자립 선언형("이제, 직접")이 낙타 시그니처다.

## 3. 수치 카드 작성법

```html
<div class="statgrid">
  <div class="statcard">
    <span class="statcard__n">244<small>편</small></span>
    <span class="statcard__l">계정에 남은 릴스</span>
    <span class="statcard__s">2026-01-18 ~ 2026-08-05</span>
  </div>
  <div class="statcard is-hero">…</div>   <!-- 그리드당 최대 1개 -->
</div>
```

- `__n` 숫자 / `__l` 그 숫자가 무엇인지 / `__s` 비교 기준·기간. **세 칸을 다 채운다.** `__s`가 없으면 숫자가 허공에 뜬다.
- 한 그리드에 2~4장. 5장 이상이면 표로 간다.
- `.statline`(초대형 수치)은 **부마다 1회 이하**. 남발하면 무게가 사라진다.

**수치 규율 (어기면 통삭제)**
- 모든 숫자는 `정본수치표_260808.md`에서만. `퍼널정량_260806.md`의 옛 값(76.6% · 21.9→10.1 · 27,000/19,000)은 **폐기됐다.**
- 반올림 표기는 카드 상단(`244편`·`78.6%`), 정확값은 `__s`나 본문에(`7,514,000`).
- **표본 수·측정 사정·"실측"은 본문에 쓰지 않는다.** 수치는 결론의 언어로만("중앙 15,000"). 방법론은 전부 부록 C.
- "전수 분석했다" 류 서사 금지. 244는 우리 작업량이 아니라 **그 계정의 사실**이다.

## 4. 인용 작성법

조니 발언 — 반드시 `조니_합의사항_니즈_정리.md`의 검증된 인용만, **원문 그대로**:

```html
<blockquote class="quote">
  <p class="quote__t">"…원문…"</p>
  <span class="quote__by"><b>조니</b> · 2026-07-07 착수 미팅</span>
</blockquote>
```

릴스 캡션·광고 온스크린 텍스트 등 자료 원문:

```html
<div class="capquote">
  <span class="capquote__meta">메타 광고 소재 · 이미지 · 2026.5.17 집행</span>
  <p class="capquote__t">여러 줄 원문은 그냥 줄바꿈 (white-space:pre-line)</p>
</div>
```

- 각색·요약·매끄럽게 다듬기 **금지.** 조사 하나 바꾸지 않는다.
- 전사 화자 라벨은 신뢰할 수 없다 → 합의사항 정본에서 **조니 발언으로 판정된 것만** 쓴다.
- 타임코드는 `quote__by`에 넣지 않는다(내부 정보). "2026-07-07 착수 미팅"까지만.
- 한 절에 인용 2개를 연속으로 놓지 않는다. 사이에 해석 문단이 온다.

## 5. 임베드 카드 작성법

```html
<div class="embed-card">
  <div class="embed-card__head">
    <span class="embed-card__rank">01</span>
    <span class="role-chip r-in">유입</span>
    <span class="embed-card__v">751<small>만</small></span>
  </div>
  <p class="embed-card__hook">처음부터 잘맞는 고부는 없는것같아요</p>
  <p class="embed-card__date">2026-01-27 · 7,514,000</p>
  <div class="ig-well">
    <blockquote class="instagram-media"
      data-instgrm-permalink="https://www.instagram.com/reel/DUAXnreCUIj/"
      data-instgrm-version="14"></blockquote>
  </div>
  <a class="embed-card__link" href="https://www.instagram.com/reel/DUAXnreCUIj/"
     target="_blank" rel="noopener"><span>인스타그램에서 보기</span><span>↗</span></a>
</div>
```

- **핵심 규칙: 플레이어가 안 떠도 인접 문장과 메타 라벨만으로 어떤 근거인지 식별할 수 있어야 한다.** 원본 링크는 항상 접근 가능한 보조 링크로 남긴다.
- 최종본은 계정명·프로필·캡션·댓글이 붙는 인스타그램 공식 임베드 대신, 사용 권한이 확보된 원본 영상 또는 포스터 프레임을 자체 플레이어로 렌더링한다. 순수 콘텐츠 영역만 보이고 날짜·조회수 라벨은 프레임 위에 겹쳐 표시한다.
- 역할 칩: `r-in` 유입 / `r-tr` 신뢰 / `r-cv` 전환 / `r-mx` 혼합. **이 4색은 문서 전역에서 같은 뜻이다** — 도해에서도 같은 색을 쓴다.
- URL은 `tags_260806.jsonl`의 `id`로 조립: `https://www.instagram.com/reel/<id>/`
- `__hook` 텍스트도 jsonl의 `hook` 원문 그대로.
- 2장짜리 대조는 `.embed-grid.embed-grid--2`(나란히 그리드), 다수 나열은 `.embed-grid`.
- **임베드 배치 규칙 (낙타 확정 2026-08-08):** 임베드는 한곳에 몰지 않고 언급 문단 옆에 분산한다. 한 지점에 3장 이상 몰리면 바둑판 그리드 금지 — `.embed-grid`는 가로 슬라이드(flex + scroll-snap)로 렌더된다. 스킨을 이식할 때 이 슬라이드 동작(`display:flex; overflow-x:auto; scroll-snap-type:x mandatory`)을 유지할 것.
- **재언급 규칙 (낙타 확정 2026-08-09):** 이미 한 번 제시한 콘텐츠는 작은 텍스트 트리거로 표시한다. `mouseenter`·`focus`에서 순수 콘텐츠 영역의 미리보기를 띄우고, `mouseleave`·`blur`에서 닫는다. 클릭은 최초 임베드의 앵커로 이동한다. 터치 환경에서는 첫 탭으로 미리보기를 열고 두 번째 탭으로 이동한다.

## 6. 다이어그램 작성법

**부마다 최소 1점.** 본문이 말한 것을 도해가 한 번 더 보여준다(낙타 확정 원칙).

```html
<figure class="figframe" id="fig-xxx">
  <span class="figframe__num">도해 03 — 제목</span>
  <div class="figframe__box">
    <svg viewBox="0 0 720 340" role="img" aria-label="시각장애 사용자용 한 문장 설명">…</svg>
  </div>
  <figcaption class="figcap">도해가 <b>무엇을 말하는지</b> 한 문장.</figcaption>
</figure>
```

SVG 규칙:
- `viewBox`만 쓰고 `width`/`height` 속성은 쓰지 않는다(CSS가 100%로 늘린다).
- **색을 하드코딩하지 않는다.** 전부 `var(--r-in)`·`var(--border-strong)`·`var(--r-tr-fill)` 등 토큰 참조. 스킨 교체 시 함께 바뀌어야 한다.
- 텍스트 클래스: `.d-lab`(라벨) `.d-sub`(메타) `.d-num`(수치) `.d-note`(주석) `.d-note--mute`(약한 주석).
- **`<text>`에 `fill="…"` 속성을 쓰지 말 것** — CSS 클래스가 이깁니다. 색을 덮으려면 `style="fill:var(--r-cv)"`.
- 없는 관계를 그리지 않는다. 0부 도해 02는 "연결이 없다"를 점선과 ✕로 그렸다 — 이게 이 문서의 도해 문법이다.
- 부별 지정 도해는 CP2 스펙 주석에 이미 박혀 있다. 임의로 바꾸지 않는다.

## 7. 실험 카드 (7부)

```html
<div class="expcard">
  <span class="expcard__no">CARD 01</span>
  <h4 class="expcard__t">서사 재고 이관</h4>
  <dl>
    <dt>가설</dt><dd>…</dd>
    <dt>실행</dt><dd>…</dd>
    <dt>판독</dt><dd>90일 신뢰형 중앙뷰 <b>9,708</b> 대비 …</dd>
    <dt>폐기</dt><dd>4주 연속 … 이면 중단</dd>
    <dt>주기</dt><dd>주 1회</dd>
    <dt>차이</dt><dd>이미 해보신 것과의 차이 — …</dd>
  </dl>
</div>
```

- 6개 항(가설·실행·판독·폐기·주기·차이)을 **전부** 채운다. 폐기 기준 없는 카드는 카드가 아니다.
- 판독 임계는 **정본수치표의 본인 베이스라인**에서만. 임의 숫자 금지.
- "차이" 항은 ENTP 대응 장치다 — 조니는 대부분 기시도했다. "이건 해봤는데요"에 선제 응답한다.

## 8. 개작 전후 쌍 (2부·5부)

```html
<div class="ba">
  <div class="ba__col"><span class="ba__tag">개작 전</span><p class="ba__body">…</p></div>
  <div class="ba__col ba__col--after"><span class="ba__tag">개작 후</span><p class="ba__body">…</p></div>
  <div class="ba__why">왜 애프터가 더 세게 먹히는가 — 한 줄.</div>
</div>
```

- 라벨은 반드시 **"개작 전 / 개작 후"**. "비포/애프터"는 피부 사진과 혼동된다(스펙 명시).
- 애프터는 조니 실제 릴스 카피·캡션을 손본 것이어야 한다. **상상 예문 금지.**
- `.ba__why`는 규제 회피 설명이 아니라 **왜 더 먹히는지**를 쓴다. 5부 논지: "약해지는 게 아니라, 더 센 화법이 마침 합법이다."

## 9. 문장 규율 (교정 7축 + 콜드리드)

문단 브리핑 순서는 **상황 → 의미 → 지시 → 근거**.
모든 처방 문장은 **욕구 → 니즈 → 실행** 순.

1. **평가어 대신 실물 명사.** "훌륭한 서사 자산"(✕) → "49건의 촬영된 대본"(○)
2. **상상 사례 금지.** 예시는 실제 릴스·실제 광고 소재·실제 발언에서만.
3. **뭉뚱그리지 말고 전개.** "여러 문제가 있습니다"(✕) → 문제를 하나씩 이름 붙여 편다.
4. **아포리즘 삭제.** 멋있게 끝나는 한 줄을 문단 끝에 붙이지 않는다.
5. **구조는 명시.** "이 절은 A → B → C 순으로 간다"가 필요하면 쓴다. 눈치로 알게 하지 않는다.
6. **급 존중.** 조니는 월매출 1억, 광고를 인하우스로 돌리는 운영자다. 초심자 설명·용어 풀이 금지.
7. **방법론 은닉.** 수치는 결론의 언어로. 어떻게 알아냈는지는 부록 C에만.

어휘:
- **"다정" 금지 → "고객 편에 서는 순간".** 문서 전역 예외 없음.
- "비포/애프터" → 어법·표현 맥락에서는 "개작 전/후".
- 감성 어휘·감성 톤 금지. 조니가 명시 거부한 방향("착한 척 하는 느낌")이다.
- **브랜드 표기 (낙타 확인 2026-08-10).** 상단 바·푸터의 영문 표기는 **`RE:FEEEL & AD solution`** 이다 —
  `AD solution`이 이 브랜드의 공식 영문 표기이므로 `AD Solution`·`ADSolution`으로 고치지 않는다.
  **본문 국문은 예외 없이 `AD솔루션`**(붙여 씀). 영문 표기와 국문 표기가 함께 있는 것은 혼용이 아니라
  로고 표기와 본문 표기의 층이 다른 것이다.
- **`퍼스널브랜드`는 붙여 쓴다** (낙타 확정 2026-08-10). `퍼스널 브랜드`로 띄우지 않는다.

## 11. 스킨 교체 지점

스킨 패스는 **`index.html`의 `<style>` 블록 하나만** 건드린다. 마크업은 손대지 않는다.

### 교체 절차
1. `<style>` 앞 주석 블록(`SKIN LAYER — 잠정`)부터 `</style>`까지가 교체 범위다.
2. 웹폰트가 필요하면 그 주석 블록 안에 `<link>`를 추가한다. 지금은 시스템 폰트라 외부 요청이 0이다.
3. 클래스 이름을 바꾸지 않는다. 새 클래스가 필요하면 이 문서 §2에 먼저 등재한다.

### 최소 교체 = 토큰만
`:root`의 이 값들만 바꿔도 문서 인상이 통째로 바뀐다. CSS 블록 `[1] 토큰`에 모여 있다.

| 토큰 | 뜻 |
|---|---|
| `--bg` `--bg-elev` `--bg-elev-2` | 지면 / 카드 / 카드 강조 |
| `--text` `--text-dim` `--text-faint` | 본문 / 부속 / 메타 |
| `--border` `--border-strong` | 선 |
| `--accent` `--accent-ink` `--accent-soft` `--accent-line` | 강조색 / 그 위 글자색 / 옅은 면 / 밑줄·테두리 |
| `--r-in` `--r-tr` `--r-cv` `--r-mx` | 퍼널 4역할 색 (칩 + 도해 공용) |
| `--r-in-fill` … `--r-mx-fill` | 도해 면 채움 (위 4색의 옅은 짝) |
| `--sans` `--display` `--mono` | 본문 / 수치·번호 / 메타 |
| `--measure` `--w-page` `--w-rail` `--header-h` | 줄길이 / 페이지폭 / 레일폭 / 헤더높이 |

### 스킨이 바꿔도 되는 것 / 안 되는 것

**바꿔도 됨** — 색, 서체, 라운딩, 여백 리듬, 강조 방식(밑줄↔배경↔색), 히어로 조판, 카드 테두리 스타일.

**바꾸면 안 됨**
- **팔레트 4색+파생 램프+형광펜 예외 외의 색 금지 — 빌드 검증이 감시한다.** 허용 목록은 `cp10_full_style.css` 상단 주석(Pure White #ffffff · Deep Charcoal #13171b · Signal Blue #0030cf · Cloud Mist #d7e1ec + 차콜 파생 쿨그레이 · Signal Blue 명도 램프 · Cloud Mist 알파 변형 + 형광펜 #b9d9fe/#0c51cb). `node render_cp10_full.js`가 CSS·렌더러·산출 HTML·부록 페이지를 전수 대조해 `[팔레트 위반]`으로 보고한다.
- **퍼널 4색의 구분성.** `--r-in/tr/cv/mx`는 데이터 인코딩이다. 색을 바꾸는 건 자유지만 네 색이 서로 구별되어야 하고, 칩과 도해가 **같은 색**을 써야 한다.
- **`--measure`(줄길이 상한)를 크게 늘리는 것.** 본문이 45em을 넘으면 읽기 리듬이 깨진다.
- **`.embed-card`에서 메타(조회수·역할·훅·링크)를 숨기는 것.** 임베드 실패 시 근거가 통째로 사라진다.
- **`svg` 안에 색 하드코딩.** 토큰 참조 원칙은 스킨과 무관하게 유지한다.
- 클래스 이름, `id`(`p0`~`pa`), `data-t` 값 — 네비 JS가 이 이름들에 붙어 있다.
- **이탤릭(기울임) 전면 금지 (낙타 확정 2026-08-10).** 이 문서군은 기울임을 쓴 적이 없다. `font-style:italic`/`oblique`를 CSS·인라인 스타일 어디에도 두지 않고, `<em>`·`<i>`·`<cite>`는 구조·아이콘 용도로만 쓰되 렌더는 정체(正體)로 강제한다(`em,i,cite,address,dfn,var,q{font-style:normal}` 전역 리셋). 강조는 **굵기와 팔레트 색**으로만 한다. 렌더러에 `*텍스트*` → 이탤릭 변환 경로를 만들지 않는다(현재 `**굵게**`·백틱만 처리). 빌드가 `[이탤릭]`으로 전 소스를 감시한다 — 0건 유지.
- **3칸 그리드는 좌우 대칭이다 (CP12 §20 CA).** `[바깥 52 | 레일 200 | 거터 44 | 본문 720 | 거터 44 | 우측트랙 200 | 바깥 52] = --shell 1312`. 거터는 `--gutter` 하나뿐이고(레일쪽/주석쪽을 따로 두지 않는다), `--rail == --note` 라서 본문 칸이 화면 정중앙에 온다. `--shell`을 키우면 본문 칸이 `--prose`를 넘어서면서 **주석이 예약된 우측 트랙 칸을 벗어난다** — 셋(`--shell`·`--rail`/`--note`·`--gutter`)은 항상 같이 계산한다.
- **좌측 레일 라벨은 잘리지 않는다 (CP12 §20 CC).** `white-space:nowrap`·`text-overflow:ellipsis`·`-webkit-line-clamp`를 레일에 쓰지 않는다(모바일 가로 레일만 예외). 긴 절 제목은 `word-break:keep-all`로 감긴다. 세로로 넘칠 땐 간격·폰트를 단계적으로 조밀하게 — **스크롤바는 금지**. 빌드 `[레일]`이 잘림 유발 속성과 폭 초과 어절을 0건으로 감시한다.

### JS는 스킨과 분리돼 있다
문서 하단 `<script>` 4개(진행률 · 부 네비 · 레일 소목차 · 인스타 임베드)는 클래스/id에만 의존한다.
스킨을 갈아도 손댈 일이 없다. 마지막 비콘 스크립트(`refeeel-doc-view-beacon`)는 **삭제 금지** — 열람 추적이다.

## 12. 부록 규율 (낙타 확정 2026-08-10 · CP14 + E/F/G)

부록은 **읽는 문서가 아니라 도구함이다.** "채울수록 어려워진다"는 피드백의 원인은 양이 아니라
모드였다 — 도구를 서술문으로 풀어 쓰면 독자는 매번 다시 읽어야 한다.

### 12-0. 부록은 독립 페이지다 (낙타 확정 2026-08-10 · CP12 §25)

**`cp10_appendix_read.html`은 빌드 산출물이 아니라 손으로 유지하는 정본이다.**
`render_cp10_full.js`는 이 파일을 **쓰지 않는다** — 생성하는 파일은 `cp10_full_report.html`·
`cp10_mark.html` 둘뿐이고, 부록은 링크·팔레트 검증을 위해 **읽기 전용**으로만 연다.

- **`BUILD:*` 마커와 `fs.writeFileSync(부록)` 경로를 다시 만들지 않는다.** 예전 구조에서는
  부록을 손으로 고친 뒤 빌드를 한 번만 돌려도 그 편집이 MD 원문으로 덮여 조용히 사라졌다.
  경고 주석으로 막을 수 없어서 구조 자체를 없앴다.
- MD 정본(`CP10_…v3`)의 부록 A·B 섹션은 **삭제하지 않고 보관**한다. 렌더러는
  `data-group="appendix"` 슬라이스를 본편 본문에서 잘라내기만 하고 출력하지 않는다.
- **스타일은 공유 CSS 한 곳에만 있다.** 부록 `<head>`는
  `<link rel="stylesheet" href="cp10_full_style.css">` 하나뿐이고, 부록 전용 규칙은
  같은 파일 말미 **`[CJ] 부록 레이어`** 에 산다. 부록 HTML에 인라인 스타일 블록을 다시 만들지 않는다 —
  만드는 순간 본편과 부록의 톤이 갈라진다. CSS 한 곳을 고치면 양쪽에 동시 반영된다.
  (본편은 빌드 때 이 파일을 인라인한다 — **CSS만 고치고 빌드를 안 돌리면 본편에는 반영되지 않는다.**)
- 부록을 손대는 작업은 **착수 전 `md5`·mtime을 잡고 끝에 다시 대조한다**(동시 편집 사고 이력 §24-7).
- 앵커 id의 정본은 **부록 파일의 실제 id**다. 본편 MD의 딥링크를 그 id에 맞추는 방향으로 고치고,
  반대로 사람이 고친 부록 id를 MD에 맞춰 바꾸지 않는다.

### 12-1. 새 개념 금지 (원칙)
**부록에서 새로운 개념을 처음 등장시키지 않는다 — 부록은 본문에서 이미 나온 것의 실행 버전이다.**
부록에만 있는 용어를 발견하면 둘 중 하나다: 본문으로 올리거나, 삭제한다.
과거 위반 사례 — `정박층`(본문 0회, 부록에만 존재 → `캐러셀(고정 게시물)`로 교체),
`이동중앙`(→ `최근 4주 중앙값`), `본인 베이스라인`(→ 판독 1의 기준선으로 흡수).

### 12-2. 탭은 자료의 종류가 아니라 사용 시점으로 나눈다
① 발행 전 점검 · ② 실물 예시 · ③ 성과 판독 · ④ 분석 근거.
첫 화면은 탭 이름보다 **상황 문장이 먼저** 온다(`.ap-router` — "지금 무엇을 하려고 오셨나요?").

### 12-3. 각 탭은 3블록
① 무엇을 판단하나(`.tab-when` 한 문장) → ② 판단 도구(체크리스트·표) → ③ AI 프롬프트.
**도구가 위, 설명이 아래.** 설명 문장은 최대 2줄이고 나머지는 본편 링크나 `<details class="howto">` 접기로 내린다.

`.tab-when`은 **탭 바 바로 아래 한 줄**이다(L1) — 면·테두리·라벨 칩 없이 12.5px muted 텍스트만.
패널 안의 `p` 규칙이 id 선택자라 `.tab-when`을 이기므로 `#panel-*>p.tab-when`으로 같이 잠근다.
부록 헤더에는 목차·라우터 박스를 두지 않는다(L2) — 탐색은 좌측 레일 + 탭 바가 맡는다.

### 12-4. AI 도구는 작업 단위로 3종 (낙타 확정 2026-08-10 · 구 "프롬프트 하나 + 모드" 폐기)

**모드 번호를 적어 하나의 프롬프트를 갈아 쓰는 구조는 폐기했다.** 사용자가 "몇 번 모드지"를
다시 판단해야 했고, 한 프롬프트에 세 작업의 기준을 다 담으면서 어느 것도 충분히 못 담았다.
현재 구조는 **작업 하나 = 도구 하나**이고, 도구를 통째로 복사한다.

| 도구 | id | 언제 |
|---|---|---|
| ① 발행 전 판정 | `prompt-publish` | 이 기획을 촬영·발행해도 되는가 |
| ② 성과 분류·계산 | `prompt-performance` | 최근 90일 기준선은 얼마인가 |
| ③ 표현 1차 검수 | `prompt-expression` | 최종 카피의 위험과 대안은 무엇인가 |

- 세 도구는 전부 **발행 전 점검 탭** 한 곳에 산다. 다른 탭에서는 `.tool-jump` 상자가
  해당 도구의 id로 직접 보낸다("모드 N을 적으세요"라고 쓰지 않는다).
- 도구 안에는 **그 작업이 쓰는 판정 기준 전문**이 들어간다("부록 참조" 금지 — 기준을 빼면
  분기마다 다른 잣대로 분류돼 시계열 비교가 성립하지 않는다).
- 공통 규칙 4개: 기준 전문 포함 · 모르면 추정 말고 되묻기 · 인과 단정 금지 · 확신도 표기.
- 도구를 늘리거나 줄이면 **본편 13-7의 설명 문단과 ↗ 딥링크를 같은 커밋에서 고친다**(§12-14).

### 12-4a. 지표는 게시물 단위와 계정 단위를 섞지 않는다 (낙타 확정 2026-08-10)
게시물 원장(한 편 = 한 행: `media_id`·발행일·훅·내용 요약·브랜드/제품의 역할·`views_d7`,
선택 열 저장·도달·팔로우)과 계정·기간 지표(기간·프로필 방문·웹사이트 클릭·문의량)는
**표를 따로 둔다.** 프로필 방문류는 게시물 단위로 쪼갤 수 없어서, 한 표에 섞으면 계정 값이
특정 편의 성과처럼 읽히고 기준선이 오염된다. AI 도구의 입력 칸도 A(원장)·B(계정)로 갈라져 있다.

**조회수 표기** — 태깅 시트에 수집일 열이 없어 현재 값이 발행 후 7일 값임을 증명할 수 없다.
그래서 `7일 13,000회`처럼 확정해 쓰지 않고 **"2026-08-05 수집 스냅샷 기준 중앙 조회수 N회"**로
쓰고, "다음 분기부터 발행 후 7일 고정값(`views_d7`)으로 갱신합니다"를 함께 적는다.
기준선 표에는 표 바로 아래에 같은 단서를 붙인다.

### 12-5. 판정 기준은 정의문이 아니라 질문형
`전이: 브랜드 자격으로 이동`(✕) → `브랜드나 제품을 지워도 이야기가 그대로 성립하는가?`(○)
코드값(J·X·C·P)은 **분석 근거 탭의 데이터 시트에서만** 쓴다.

### 12-6. 수치에는 해석 문장을 병기한다
`전이 도달 생존선 9,012`만 쓰지 않는다 →
`최근 90일 전이 콘텐츠의 절반이 이 위에 있다는 뜻입니다. 넘지 못했다면 실패가 아니라 도달 설계를
점검하라는 신호입니다.` 기준선 표는 `이 숫자가 뜻하는 것` 열을 반드시 갖는다.

### 12-7. 실행 가능성 — "조니가 실제로 할 수 있는가"
할 수 없는 것은 무리해서 넣지 않는다. 아래는 금지 유형이다.
- **채널 대조 처방 금지.** 인스타 지표와 자사몰 일매출을 함께 보게 하는 절차는 넣지 않는다 —
  광고·검색·추천이 섞여 인과를 분리할 수 없고, 13부 도입의 한계 고지와 정면으로 모순된다.
  지표는 **계정 안에서 완결되는 것**만(조회·저장·프로필 방문 + 댓글·DM에 등장한 말).
  매출은 "참고로 보되 개별 콘텐츠와의 인과는 추정하지 않습니다" 한 줄로 끝낸다.
- **다중 실행 카드 금지.** 카드 9종처럼 병렬 운영을 요구하는 구조는 넣지 않는다.
  대체는 한 장짜리 판독 루틴(무엇을 보는가 → 언제 채택 → 언제 폐기) 하나.
- **매주 수기 기록은 한 줄 이내.** 주간 시트는 5분 안에 채워져야 하고, 칸은 전부 계정 안 지표다.
- 임계값은 정본 기준선에서 파생된 값만 쓴다. 60%·90% 같은 배수를 새로 만들지 않는다.

### 12-8. 푸터·상단 바는 뷰포트 전체 폭 (CP12 §22 H)
`.top`/`.site-footer`는 `.shell` **바깥**에 두고, 내부 래퍼(`.top-inner`/`.footer-inner`)가
`max-width:var(--shell); padding:0 52px`로 정렬을 맞춘다. `100vw`·음수 마진 트릭을 쓰지 않는다
(스크롤바 폭만큼 가로 넘침이 생긴다).

### 12-9. 부록은 예외 없이 본문 폭 720px (I-2 → CP12 §24로 개정)
**부록 안에서 `--wide`(964px)는 쓰지 않는다.** 텍스트든 표든 링크박스든 프롬프트든 전부
`--prose`(720)에 맞춘다 — 왼쪽 정렬선 하나, 오른쪽 끝선 하나. 1440px 기준 본문 칸은 `[360 … 1080]`이고
부록의 모든 요소가 1080에서 끝난다.

**왜 964를 폐기했나.** 964 = 본문 720 + 거터 44 + 우측트랙 200이다. 정의상 964로 늘린 요소는
**우측 주석 트랙을 통째로 차지한다**. ① '발행 전 점검' 탭은 주입된 `.chapter`가 `.visual-aside`를
그 트랙(`[1124 … 1324]`)에 실제로 띄우고 있어 겹침이 났고, ② 주석이 없는 탭에서도 본문(1080)과
표·박스(1324)의 오른쪽 끝이 244px 어긋나 "정렬이 깨져 보인다"는 실사용 보고로 돌아왔다.

**폭이 모자라면 넓히지 말고 자기 안에서 가로로 스크롤한다.**

| 요소 | 처리 |
|---|---|
| `.table-wrap` (패널 직계 · 주입 `.chapter` 안 모두) | `overflow:auto` — 공용 CSS 그대로 |
| `.tags-scroll` (태깅 시트, 내용 폭 2,026px) | `overflow:auto` + 머리행·첫 열 sticky |
| `.promptbox__code` | `white-space:pre` + `overflow:auto` — 720에서도 원문 줄 수 = 렌더 줄 수 |
| `.csv-box`·`.tags-legend`·`.tags-toolbar`·`.tags-filters`·`.tags-empty`·`.tool-jump` | 720에 맞춰 접힘(flex-wrap) |

`#panel-*{max-width:var(--wide)}`(패널 통째 확장)도, `@media(min-width:1100px)` 요소 확장 블록도
다시 만들지 않는다. 광폭 도해(`.visual--wide`, 964)는 **본편에만** 있고, 그쪽은 주석을 도해 아래로
내려(`margin-left:auto;width:var(--note)`) 겹침을 피한다 — 부록에는 `.visual--wide`가 0건이다.

**회귀 검사** — 부록 4탭 × 1440/1200/980/780에서 모든 블록 요소의 `getBoundingClientRect().right`가
본문 칸 오른쪽 끝과 같아야 한다. 예외로 허용되는 것은 둘뿐이다: 우측 주석 트랙에 사는 것
(`.visual-aside`·`.v-cap`·`.v-note`·`.v-ptr`)과, 자체 스크롤 컨테이너 안에서 클리핑되는 `#tags-table`.
`document.documentElement.scrollWidth == window.innerWidth`(가로 넘침 0)도 함께 본다.

### 12-10. 서체는 본문 sans 하나 (I-3)
본문·제목·표·라벨·레일·칩 전부 `body`의 sans 스택을 상속한다. **예외는 둘뿐** —
코드/프롬프트(`var(--mono)`: `.promptbox__code`·`pre.promptbox`·`code`)와
수치 정렬용 `font-variant-numeric:tabular-nums`(`.c-views`·`.tags-toolbar__l b`).
모노 스택은 `--mono` 토큰 하나로만 쓰고 개별 선언에 스택을 다시 적지 않는다.
display·serif 서체는 문서 어디에도 두지 않는다.

**규칙이 하나도 안 걸려 UA 기본 조판으로 떨어지는 것도 이 절의 위반으로 본다 (CP12 §25-4).**
`font-family`를 잘못 준 적은 한 번도 없었지만, `<ol class="badge-list sheet-rules">`가
`.chapter ol.badge-list`(조상 `.chapter` 없음)에도 `ul.sheet-rules`(요소는 `ol`)에도 안 걸려
16px·`line-height:normal`·decimal로 떨어졌고, 주변 본문(15px/1.85)과 리듬이 어긋나
"이 목록만 다른 서체"라는 보고로 돌아왔다. **패널 직계에 놓는 목록·박스는 `.chapter` 후손 선택자에
기대지 말고 자기 클래스로 조판을 명시한다.** 강조가 필요하면 서체·크기를 건드리지 말고
12-13의 면 박스를 쓴다.

### 12-11. 탭 아이콘 (J)
탭 버튼과 라우터에서 번호(①②③④)를 쓰지 않고 **인라인 SVG 선 아이콘**을 라벨 앞에 둔다.
`viewBox="0 0 24 24"` · `fill:none` · `stroke:currentColor` · `stroke-width:1.6` · round cap/join · 16~17px ·
`aria-hidden="true" focusable="false"` + 텍스트 라벨 유지. 색은 `currentColor`만 — 활성 탭 색이 자동으로 따라온다.
외부 아이콘 라이브러리·이미지 파일 금지. 매핑: 발행 전 점검 = 클립보드-체크 / 실물 예시 = 레이어 카드 /
성과 판독 = 오름 막대 / 분석 근거 = 데이터베이스.
**탭 번호가 없으므로 본문에서 "탭 ①" 식으로 가리키지 않는다 — 탭 이름으로 부른다.**

### 12-12. 프롬프트 박스는 터미널 (K)
`.promptbox`는 Deep Charcoal 면 + Cloud Mist 글자 + `--mono`. 구조는
`.promptbox > .promptbox__bar(.promptbox__toggle + .promptbox__copy) + .promptbox__wrap > pre.promptbox__code`.
- **기본 접힘.** 헤더 줄 클릭·Enter로 펼친다. `aria-expanded`/`aria-controls`를 단다.
- 접힘은 `.promptbox__wrap{max-height:0;visibility:hidden}` → `.is-open`에서 `min(62vh,620px)`.
  `visibility`로 접근성 트리에서도 빠지고, `max-height` 전환으로 높이가 튀지 않는다.
- 펼쳐진 본문은 `pre`가 **자기 안에서 세로 스크롤**한다(페이지가 길어지지 않게).
- **복사 버튼은 접힌 상태에서도 동작한다.** `navigator.clipboard.writeText` → 실패 시
  textarea + `execCommand('copy')` 폴백(`file://`에서도 동작). 성공 시 아이콘이 체크로 바뀌고
  라벨이 "복사됨"으로 1.5초 유지된 뒤 되돌아온다.
- 줄바꿈이 접히면 ASCII 정렬이 깨진다. **폭을 넓혀 해결하지 않는다** — `pre`를
  `white-space:pre` + `overflow:auto`로 두면 720px에서도 접힘이 원천 차단되고, 모자라는 폭은
  `pre`가 자기 안에서 가로로 흡수한다(CP12 §24). 어느 폭에서든 원문 줄 수 = 렌더 줄 수를 실측한다.

### 12-13. 박스 역할 체계 (낙타 확정 2026-08-10 · CP12 §25-3)
**면은 두 개, 강조는 하나.** 같은 성격의 박스는 반드시 같은 면·같은 라운딩·같은 패딩·같은 테두리를 쓴다.
토큰은 `[CJ] 부록 레이어` 머리의 `--box-face`(Cloud Mist) · `--box-face-inv`(Deep Charcoal) ·
`--box-r:4px` · `--box-px:20px` · `--box-py:18px` 다섯 개뿐이고, 개별 규칙에 색·라운딩을 다시 적지 않는다.

| 역할 | 대상 | 면 | 라운딩 | 패딩 | 테두리 |
|---|---|---|---|---|---|
| S1a 블록 안내면 | `.tool-jump` · `.csv-box` · `.tags-legend` · `ul.rulebox` | Cloud Mist | 4px | 18 / 20 | 없음 |
| S1b 접기 도구 | `details.howto > summary` + `.howto-body` | Cloud Mist | 4px (열림 시 위/아래로 분할) | 헤더 13 / 20 · 본문 18 / 20 | 없음 |
| S1c 인라인 노트·칩 | `p.swap-note` · `.rw-cue` · `.rw-boundary .rw-pair` | Cloud Mist | 노트 4px · 칩 999px | 12 / 16 | 없음 |
| S1d 판정 행 | `.tbl-emph tr.emph > td` | Cloud Mist | — | 표 패딩 | 표 선 |
| S2 반전 터미널 | `.promptbox` 계열 | Deep Charcoal | 4px | bar 11/12 · code 20/22 | 흰 알파 구분선만 |
| S3 면 없는 구획 | `.tags-toolbar` · `.tags-scroll` · `.tags-empty` · `.tags-toolbar input` | 없음 | 4px | — | 1px `--line` |
| A 강조 축 | `.tool-jump__go` · `.csv-box__go` · `.tags-filters button.on` · `.tags-active em` · 활성 탭 밑줄 · 정렬 표시 | Signal Blue 면 + 흰 글자 (호버 Deep Charcoal) | 버튼 4px · 칩 999px | 10 / 16 | 없음 |

- **민트 파생 #edf2f7(`--soft`)을 부록에서 면으로 쓰지 않는다.** 면이 두 톤으로 갈라져
  "박스마다 색이 다르다"는 실사용 보고의 원인이었다. 표 얼룩만 Cloud Mist 알파
  `rgba(215,225,236,.34)`로 남긴다 — 얼룩은 박스가 아니라 데이터 텍스처다.
  (본편의 `--soft` 34곳은 도해 채움·막대 트랙이라 그대로 둔다.)
- 라운딩은 **4px(면·버튼)과 999px(칩) 두 값뿐**이다. 5px·2px·0px을 새로 만들지 않는다.
- 1차 행동 버튼의 방향은 **Signal Blue 면 → 호버 Deep Charcoal** 하나다. 반대로 쓴 버튼이 있으면 고친다.
- **회귀 검사** — 부록 4탭을 전부 켜고 `getComputedStyle(el).backgroundColor`를 훑어 면 색이
  Cloud Mist · Deep Charcoal · Signal Blue · Pure White · 반전면 위 흰 알파 **5종을 넘지 않는지** 본다.

### 12-14. 부록을 고치면 본편 MD의 부록 참조를 함께 갱신한다 (낙타 확정 2026-08-10 · CP12 §26)

부록은 손으로 유지하는 독립 파일이고 본편은 MD에서 빌드된다(§12-0). **두 파일 사이에는
빌드가 걸려 있지 않으므로, 부록만 고치면 본편은 없어진 구조를 계속 설명한다.**
실제로 부록의 AI 프롬프트를 "1개 + 모드 3"에서 "도구 3종"으로 바꾼 뒤에도 본편 13-7이
"복붙용 프롬프트는 부록에 하나로 두었습니다 / 맨 위 모드 칸에 2를 적으면…"을 그대로 말하고 있었다.
외부 검수에서 이번 납품의 **최대 결함**으로 지적된 지점이다.

**부록의 아래 항목을 바꾼 커밋은 본편 MD도 같은 커밋에서 고친다.**

| 부록에서 바뀐 것 | 함께 고칠 본편 MD |
|---|---|
| 도구·프롬프트의 개수·이름·사용법 | 13-7의 설명 문단 + `↗` 딥링크 |
| 절 제목(h3) | 그 절을 이름으로 부르는 본문 문장 + 딥링크 문구 |
| 앵커 id | 본편 MD의 `cp10_appendix_read.html#<id>` 전부 |
| 표의 열 구성·기준선 값 | 13-2~13-4·8-x 채택 기준의 인용값 |
| 용어(예: 안전 형식 → 위험을 낮추는 형식) | 그 용어를 쓰는 본문 문장 전부 |

**자동으로 따라오는 것 하나** — 본편 좌측 레일의 `부록` 그룹 하위 항목은 렌더러가
`cp10_appendix_read.html`의 `.rail-main[data-tab]` 4개에서 직접 뽑는다. 부록 탭을 늘리거나 이름을 바꾸면
본편 레일이 다음 빌드에서 자동으로 맞춰진다(추출 실패 시 MD 헤딩 기반으로 폴백). **그 밖의 참조는 전부 수동이다.**

**딥링크가 착지만 하고 아무것도 안 보이는 경우를 본다** — `.promptbox`는 기본 접힘이라, 해시로 들어온
프롬프트 상자는 라우터가 `is-open`을 붙여 펼친다. 새 접힘 컴포넌트를 만들면 라우터에 같은 처리를 추가한다.

**착수·마감 절차** — 부록을 손대기 전에 `md5`와 mtime을 잡고, 끝에 다시 대조한다(§12-0).
마감 전에는 본편이 부록을 설명하는 모든 문장을 부록 실물과 1:1 대조해 **불일치 0건**을 확인한다.
레일 레이블과 본문 h3 제목의 1:1 대조도 함께 돈다(브라우저에서
`nav.rail .rail-sub a` → `getElementById(href)` 텍스트 비교).
